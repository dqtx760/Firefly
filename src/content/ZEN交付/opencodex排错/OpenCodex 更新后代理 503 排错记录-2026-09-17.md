
> 场景：`npm install -g @bitkyc08/opencodex@latest` 升级 OpenCodex 后，Codex 通过本地代理 `127.0.0.1:10100` 调用时报 503，提示包文件变化需重启。
> 目标：定位仍在运行旧版本代码的代理进程，强制终止并让 wrapper 用新版本拉起。

---

## 一、错误现象

在 Codex 中使用 "Open Code Good" 套餐时，兑换/请求返回：

```
unexpected status 503 Service Unavailable:
OpenCodex package files changed while this proxy was running;
restart OpenCodex before retrying.,
url: http://127.0.0.1:10100/v1/responses
```

---

## 二、环境快查

| 项 | 值 |
|---|---|
| 包名 | `@bitkyc08/opencodex` |
| 升级前版本 | `2.36.0` |
| 升级后版本 | `2.56.0` |
| 代理地址 | `http://127.0.0.1:10100` |
| 代理运行时 | Bun（占用端口的进程是 `bun.exe`） |
| 平台 | Windows 11 |

---

## 三、根因

OpenCodex 在启动本地代理时，会缓存包的文件路径/版本指纹（用于校验和健康检查）。`npm install -g` 在更新时会把旧包目录替换成新目录（通常移到 `.opencodex-<hash>` 临时目录再删除）。但**进程内已加载的代码仍指向已被删除或重命名的旧路径**，代理在收到请求时校验失败，主动返回 503 并要求重启。

关键点：
- 503 是代理**主动**抛出的，不是上游错误，也不是网络错误
- `/healthz` 可能仍然 200，因为健康检查路径不校验包指纹
- 只有真正调用 `/v1/responses` / `/v1/models` 时才会撞到

---

## 四、排错过程

### 1. 确认端口监听状态

```bash
netstat -ano | findstr ":10100.*LISTENING"
```

输出：

```
  TCP    127.0.0.1:10100        0.0.0.0:0              LISTENING       11068
```

→ 端口被 PID `11068` 占用，代理确实还活着。

### 2. 识别进程

```bash
tasklist /FI "PID eq 11068"
```

输出：

```
bun.exe                      11068 Console                    1    135,100 K
```

→ 是 `bun.exe`，OpenCodex 内置代理的运行时进程。

### 3. 优雅终止（失败）

```bash
taskkill /PID 11068 /T
```

输出（关键行）：

```
错误: 无法终止 PID 11068（属于 PID 8860 子进程）的进程。
原因: 只能强制终止该进程（用 /F 选项）。
```

→ `bun.exe` 拉起了子进程（PID 8860），普通 `taskkill` 拒绝终止进程树。

### 4. 强制终止（成功）

```bash
taskkill /PID 11068 /T /F
```

输出：

```
成功: 已终止 PID 11068（属于 PID 8860 子进程）的进程。
```

### 5. 验证端口释放

```bash
netstat -ano | findstr ":10100.*LISTENING"
# 输出为空 → 端口已释放
```

### 6. 重启 Codex 验证

重新打开 Codex，Codex 拉起新版 OpenCodex 代理（v2.56.0），兑换流程恢复正常。

---

## 五、解决方案速查

直接给答案版：

```bash
# 1. 找到占用 10100 的 PID
netstat -ano | findstr ":10100.*LISTENING"

# 2. 强制终止进程树
taskkill /PID <PID> /T /F

# 3. 重新打开 Codex，代理会用新版本自动拉起
```

## 六、预防措施

**升级前先清代理**，避免撞到同一类错误：

```bash
# 升级前杀旧代理（不会影响其他 bun 进程之外的工具）
taskkill /F /IM bun.exe

# 然后再升级
npm install -g @bitkyc08/opencodex@latest
```

> 注意：`/F /IM bun.exe` 会强杀所有 bun 进程。如果同时跑着其他 bun 工具（如 `bun run`），需要先关掉，改用 PID 精准终止。

备选：用 OpenCodex 自身的服务 wrapper（更优雅，但要求已安装服务模式）

```bash
ocx stop
npm install -g @bitkyc08/opencodex@latest
ocx start
```

`ocx stop` 会让 wrapper 停掉代理并释放端口，升级后 `start` 用新版本拉起。
