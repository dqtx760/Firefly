# Codex 话术 — 博士论文撰写 Skill 构建

> 将以下内容完整复制粘贴到 Codex 对话框，它会自动帮你构建整套论文撰写工作流。

---

## 话术开始

你是一个学术论文撰写助手。我的 Obsidian 知识库已经有完整的目录结构，请先阅读 `00-首页/` 下的规则文件和 `00-首页/index.md`，理解整个知识库的组织方式。

我的知识库是五层结构：

- `01-输入/`：原始材料（论文PDF、网页剪藏、审稿意见、数据说明、选题灵感）
- `02-处理中/`：项目工作台（每个论文项目一个子目录）
- `03-Wiki/`：已编译知识网络（source、claim、theory、variable、method、dataset、project）
- `04-作品/`：正式稿件、投稿包
- `05-参考/`：模板、期刊指南、提示词库

每个论文项目的标准子目录是：`manuscript/`、`文献矩阵/`、`R1-审稿意见与回复信/`、`R1-manuscript/`、`R2-审稿意见与回复信/`、`R2-manuscript/`。

现在请帮我创建一套完整的论文撰写工作流 Skill，包含以下 6 个阶段。每个阶段的 prompt 都要能独立调用，但遵循固定流程顺序。所有路径必须严格对齐我的目录结构，不要创建任何新目录。

### 第二步：创建论文撰写 Skill

---

#### 阶段 1：文献调研 — 寻找研究灵感

```
你是学术研究助手。请基于我 Obsidian 知识库中已有的文献，帮我寻找一个值得深入研究的主题。

第一步：阅读知识库
1. 先读取 00-首页/index.md 和 00-首页/rules/ 下的规则文件，理解知识库结构
2. 读取 03-Wiki/sources/papers/ 目录下的所有论文 source 页面
3. 读取 03-Wiki/claims/empirical-findings/ 下的已有实证发现
4. 读取 03-Wiki/syntheses/research-gaps/ 下的已有研究空白分析
5. 读取 02-处理中/99-候选项目/ 下已有的候选方向

第二步：分析并提出候选主题
基于文献中的 research gaps、future research suggestions、underexplored areas，提出 3-5 个候选主题。每个候选主题需要包含：
- 主题名称（中英文）
- 研究问题是什么
- 为什么这个主题值得研究（基于哪些文献的gap）
- 预期需要什么类型的数据
- 初步可行性判断（数据可得性、方法复杂度）

第三步：写入知识库
- 将候选主题写入 02-处理中/99-候选项目/ 对应的文件
- 最终推荐一个最有潜力的主题，并说明推荐理由
```

#### 阶段 1.5：数据分析与变量构建（分 4 个子步骤）

**子步骤 1A：确定数据需求**

```
研究主题已确定为：[主题名称]

请基于这个研究主题，帮我确定需要哪些数据。

要求：
1. 先阅读 03-Wiki/datasets/ 下已有的数据集信息
2. 阅读 01-输入/ 中与数据库说明书相关的文件（如有）
3. 明确数据来源（哪个数据库：CSMAR、Wind、CNKI、World Bank、OECD 等）
4. 列出需要下载的具体数据表/文件
5. 说明每个数据的字段含义
6. 说明数据的时间范围和样本范围要求

写入知识库：
- 数据需求清单写入当前项目目录的 manuscript/ 下
- 数据库字段信息写入 03-Wiki/datasets/ 对应文件
- 原始数据库说明书保留在 01-输入/ 原位，不移动
```

**子步骤 1B：变量构建**

```
我已经下载了数据。请帮我构建研究变量。

要求：
1. 先阅读 03-Wiki/variables/ 下已有的变量定义
2. 阅读 03-Wiki/methods/ 下已有的方法论信息
3. 阅读当前项目 manuscript/ 下的数据需求文件
4. 为每个变量定义：
   - 变量名称与符号（如 X1、Y、Z）
   - 变量定义（精确的计算公式）
   - 数据来源（具体表名和字段名）
   - 理论含义（为什么选这个变量）
   - 处理方式（对数、缩尾、标准化等）

写入知识库：
- 变量定义写入 03-Wiki/variables/ 对应文件
- 生成 Python/Stata 数据清洗代码，写入当前项目 manuscript/
```

**子步骤 1C：初步回归**

```
变量已经构建完成。请帮我跑初步回归分析。

要求：
1. 阅读 03-Wiki/variables/ 中的变量定义
2. 阅读 03-Wiki/methods/ 中的模型设定参考
3. 设计回归模型（包括被解释变量、核心解释变量、控制变量）
4. 生成回归代码并运行
5. 分析回归结果：系数方向、显著性、经济含义
6. 判断结果是否基本成立（是否支持一个有意义的研究故事）
7. 如果结果不成立，建议调整方案

写入知识库：
- 回归结果和代码写入当前项目 manuscript/
- 新发现的实证结论写入 03-Wiki/claims/empirical-findings/
- 方法调整记录写入 03-Wiki/methods/
```

**子步骤 1D：确认研究框架**

```
基于前面的回归结果，请帮我确认研究框架。

要求：
1. 总结回归结果的核心发现
2. 确定最终的研究主题和研究问题
3. 明确研究框架：变量关系、模型设定、预期贡献
4. 判断是否可以进入阶段 2（核心文献筛选）

写入知识库：
- 最终确定的研究框架写入当前项目 manuscript/
- 项目信息写入 03-Wiki/projects/<项目名>/
- 更新当前项目 manuscript/status.md 的阶段状态
```

#### 阶段 2：核心文献筛选（50-70篇）

```
研究主题已确定为：[主题名称]

请基于这个主题，从以下来源筛选 50-70 篇核心文献：

来源 1：03-Wiki/sources/papers/ 中已有的论文 source 页面
来源 2：Google Scholar、Web of Science 等学术数据库的网络检索

筛选标准：
1. 与研究主题直接相关（核心匹配）
2. 发表在高质量期刊（CSSCI、SSCI、SCI 优先）
3. 涵盖：理论基础、方法论、实证研究、最新进展
4. 年份分布：近 5 年为主，经典文献不限年份
5. 不能编造文献——每篇文献必须能检索到真实信息

写入知识库（严格遵循 wiki 写入规则）：
1. 为每篇文献创建 source 页面，写入 03-Wiki/sources/papers/
   - 每个 source 页面包含：标题、作者、年份、期刊、研究问题、核心方法、主要发现、与我的研究的关联
2. 从文献中提取的实证发现写入 03-Wiki/claims/empirical-findings/
3. 理论主张写入 03-Wiki/claims/theoretical-claims/
4. 机制链条写入 03-Wiki/claims/mechanisms/
5. 边界条件写入 03-Wiki/claims/boundary-conditions/
6. 文献综述综合写入 03-Wiki/syntheses/literature-reviews/
7. 生成文献列表写入当前项目 manuscript/
8. 更新 03-Wiki/log.md 操作日志
9. 更新当前项目 manuscript/status.md 的核心文献数量
```

#### 阶段 3：论文草稿撰写

```
请基于以下材料撰写论文草稿：

- 研究框架：03-Wiki/projects/<项目名>/
- 核心文献：03-Wiki/sources/papers/（筛选出的50-70篇）
- 变量定义：03-Wiki/variables/
- 实证结果：当前项目 manuscript/ 下的回归结果
- 方法论：03-Wiki/methods/

论文结构与要求：

1. **Introduction（引言）**
   - 研究背景与问题提出
   - 研究意义（理论+实践）
   - 研究框架概述

2. **Literature Review（文献综述）**
   - 按主题组织，不是逐篇罗列
   - 引用 03-Wiki/sources/papers/ 中的 source 页面
   - 找出现有研究的不足，引出我的研究空间

3. **Methodology（研究方法）**
   - 样本选择与数据来源（引用 03-Wiki/datasets/）
   - 变量定义（引用 03-Wiki/variables/）
   - 模型设定（引用 03-Wiki/methods/）

4. **Results（实证结果）**
   - 描述性统计
   - 基准回归结果
   - 稳健性检验
   - 内生性处理（如适用）

5. **Discussion（讨论）**
   - 结果解释与文献对话
   - 理论贡献
   - 实践启示

6. **Conclusion（结论）**
   - 主要发现
   - 研究局限
   - 未来研究方向

写作原则：
- 所有引用必须来自 03-Wiki/sources/papers/ 中的真实 source 页面
- 不能编造数据、结果或引用
- 使用学术英语写作
- 每章写入当前项目 manuscript/ 对应文件
- 可复用的写作段落同步写入 03-Wiki/writing/
```

#### 阶段 4：人工核验与修改

```
我将提供 Obsidian 笔记或修改意见。请：

1. 先判断修改意见对应论文的哪个部分（哪一章、哪一段）
2. 在当前项目 manuscript/ 下记录修改日志：
   - 修改日期
   - 修改位置
   - 修改内容摘要
   - 修改理由
3. 执行修改
4. 输出修改后的版本，与原文进行对比
5. 如果修改涉及引用变更，同步更新引用列表

规则：
- 不能编造新的文献来填补修改时的空缺
- 如果修改需要新文献支持，明确告知"需要补充文献"
- 区分"可以确定的结论"和"需要人工核验的内容"
- 发现待核验的 DOI、页码、引用、变量口径、数据字段或期刊等级时，统一记录到 03-Wiki/questions/ 下
- 重要修改操作写入 03-Wiki/log.md
```

```
论文修改已全部完成。请进行定稿检查：

1. 格式检查：
   - 参考文献格式是否统一（目标期刊格式）
   - 图表编号是否连续
   - 章节编号是否正确

2. 内容完整性检查：
   - 每章的核心论点是否完整

3. 质量检查：
   - 是否有逻辑断裂
   - 是否有重复表述
   - 语言是否符合学术规范

写入知识库：
- 最终版本写入 04-作品/manuscripts/
- 投稿版本写入 04-作品/submitted-versions/
- 项目总结写入 03-Wiki/projects/<项目名>/
- 更新当前项目 manuscript/status.md 为"阶段5：定稿完成"
- 更新 03-Wiki/log.md
```

## 使用指南

### 给客户的说明

1. **确保文献已入库**：你 03-Wiki/sources/papers/ 里已有的论文 source 页面越多，AI 找到好主题的概率越高
2. **复制上面的话术**：从"话术开始"到"话术结束"，完整粘贴到 Codex
3. **按阶段推进**：每次对话只做一个阶段，完成后 Codex 会更新 status.md
4. **修改阶段**：在阶段 4，直接在 Obsidian 里编辑笔记，然后把修改意见发给 Codex
5. **不要跳步**：阶段 1 → 1.5 → 2 → 3 → 4 → 5，严格按顺序

### 常见问题

**Q: 03-Wiki/sources/papers/ 里文献不多怎么办？**
A: 阶段 1 会基于已有文献分析。文献越少，AI 越依赖网络检索，质量可能受影响。建议先导入 20-30 篇基础文献。

**Q: 阶段 1.5 数据分析需要什么工具？**
A: Codex 可以生成 Python 或 Stata 代码。确保你的环境中有相应的数据分析工具。

**Q: 核心文献 50-70 篇会不会太多？**
A: 这是博士论文的标准要求。如果写期刊论文，可以缩减到 30-50 篇。

**Q: 可以回退到之前的阶段吗？**
A: 可以。在 Codex 中说明"我要回到阶段 X"，它会根据 status.md 的状态自动切换。
