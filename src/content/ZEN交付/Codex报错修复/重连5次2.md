# 本地客户端「连接被拒绝」故障排查修复提示词

> 适用报错：`os error 10061` / `connection refused` / `ECONNREFUSED` / 「目标计算机积极拒绝」。
> 这类报错本质是「连了一个没人在监听的本地端口」，不是「没网」。

## 怎么用

把下面【提示词】整段复制，连同你的报错原文/截图，一起发给任意 AI 助手（WorkBuddy / Codex / Claude 等），让它照着流程替你排查并修复。

---

## 【提示词】

```
【任务】我遇到一个本地程序联网报错，请按下面流程排查并修复，每一步都用命令输出作为依据，不要凭经验猜。

【报错原文】
（在这里粘贴你的报错，例如：stream disconnected before completion: 由于目标计算机积极拒绝，无法连接。(os error 10061)）

【第一步：先纠正判断口径】
1. 10061 / ECONNREFUSED / "连接被拒绝" = TCP 连接被目标主动拒绝，99% 是「连了没人监听的本地端口」，不是「没网」，也不是「服务器挂了」。
2. 服务器/墙的问题通常表现为 timeout（超时）、502、reset（10054）。只有出现这些才往服务端方向查。

【第二步：找出程序在连哪个代理/端口】
按优先级查这几处，把搜到的代理地址和端口记下来：
1. 程序自身配置：常见于 ~/.codex/.env、config.toml、settings.json、.env、项目内 .env.local 等
2. 环境变量：HTTP_PROXY / HTTPS_PROXY / ALL_PROXY（大小写都查）
3. 系统代理：Windows「设置 → 网络和 Internet → 代理」

【第三步：实测端口是否还活着】
1. netstat -ano | findstr "端口号"   → 看有没有 LISTENING，记下 PID
2. tasklist /FI "PID eq 该PID"       → 看是哪个进程在监听
3. curl -s -m 5 -o /dev/null -w "%{http_code}" https://www.baidu.com -x http://127.0.0.1:端口
   → 返回 200 = 代理通；返回 000 / 报错 = 端口已死

【第四步：定位根因并修复】
- 情况A：程序配置里写死的端口无监听 → 把端口改成「当前实测活着的代理端口」（先备份原文件，再改，改完验证）
- 情况B：代理客户端没启动 → 去启动它（Clash / V2ray 等），不要乱改配置
- 情况C：走系统代理但代理端口已失效 → 更新系统代理端口，或给代理客户端开 TUN 模式
- 情况D：根本没用代理、直连被墙 → 才考虑「没网/墙」的方向

【第五步：修复后的验证标准】
1. curl 走代理访问目标域名，返回 401 / 403 / 200 都算「网络已通」（401=缺鉴权、403=拦 curl UA，都是「已到达服务器」的证据）
2. 让用户完全退出程序（托盘图标退出，不是关窗口）再重开，再试一次

【硬约束】
- 改任何配置文件前必须先备份
- 端口号禁止凭记忆断言，必须 netstat 实测 + curl 验证
- 不要改动无关配置；不要泄露 auth.json / .env 里的 token、密钥
- 修完必须明确告知：改了哪个文件、改成了什么、为什么要重启程序
```

## 本次实战参考（2026-10-05，Codex 桌面版）

- 症状：Codex 流式响应中途断开，重连报 `os error 10061`。
- 根因：`~/.codex/.env` 写死 `HTTP_PROXY=http://127.0.0.1:9876`，但 9876 无进程监听；本机唯一代理是 Clash Verge 的 7890。
- 修复：备份 `.env` → 把 9876 改成 7890 → 验证走 7890 访问 api.openai.com 返回 401（网络通）。
- 结论：本地代理端口会随客户端重启/换工具而变（历史出现过 56074 / 9876 / 7890），排查时以 `netstat` 实测为准，不要沿用旧端口。
