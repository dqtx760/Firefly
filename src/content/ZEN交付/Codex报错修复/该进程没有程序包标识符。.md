Codex 弹「ChatGPT failed to start / 该进程没有程序包标识符」修复 SOP

- 记录时间：2026-09-26
- 状态：**已定位并修复**（本机实测通过，非猜测）
- 适用对象：Windows 版 Codex 桌面应用（包名 `OpenAI.Codex`，安装后界面/进程显示为 **ChatGPT**）

## 一、报错现象

弹窗标题 `ChatGPT`，正文：

```
ChatGPT failed to start.
该进程没有程序标识符。
```

只有一颗 `Quit` 按钮；点掉再启动照样弹。任务管理器里有时能看到浏览器子进程一闪而过。

> **范围提醒**：本故障只影响**桌面应用**。命令行 `codex`（`codex-cli`，本机 0.147.0，路径 `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin\codex.exe`）以及编辑器插件不受影响 —— 客户说"Codex 打不开"时，先确认他说的是桌面应用还是命令行。

**错误码释义**：`该进程没有程序标识符` = Windows AppModel 的 `ERROR_APPMODEL_NO_PACKAGE`（15700），含义是"这个进程不是以 MSIX 包身份运行的，却调用了需要包身份的 API"。

## 二、10 秒判定（先确认是不是这个故障）

```powershell
# 1) 包还在不在（输出为空 = 中招）
Get-AppxPackage -Name OpenAI.Codex

# 2) 进程是从哪启动的
Get-Process ChatGPT | Select-Object -ExpandProperty Path
#   正常：C:\Program Files\WindowsApps\OpenAI.Codex_<版本>_x64__2p2nqsd0c76g0\app\ChatGPT.exe
#   中招：C:\Users\<用户>\AppData\Local\Programs\Codex\ChatGPT.exe（散装副本，永远没有包身份）

# 3) 快捷方式指向哪
(Get-Item "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Codex.lnk" -ErrorAction SilentlyContinue).TargetPath
```

决定性证据在应用日志里：

```powershell
$d = "$env:LOCALAPPDATA\Codex\Logs\$(Get-Date -f yyyy)\$(Get-Date -f MM)\$(Get-Date -f dd)"
$f = Get-ChildItem $d -Filter *.log | Sort-Object LastWriteTime -Descending | Select-Object -First 1
Select-String -Path $f.FullName -Pattern 'bootstrap-import-main|程序包标识符|packaged='
```

| 状态 | 日志特征 |
| --- | --- |
| 中招 | `error Desktop bootstrap failed to start the main app phase=bootstrap-import-main` + `error [sparkle] Failed to set up updater … 该进程没有程序标识符` |
| 正常 | 上面两条都不出现；启动后会看到 `[sparkle] in_app_updates_policy_wait_started`，并很快出现正常工作记录（`git-repo-watcher`、`git.command.complete` 等） |

> ⚠️ 别把日志里的 `packaged=true/false` 当唯一依据：早期版本从散装路径启动时也会打 `packaged=true`，而它的 updater 依然因"无包身份"初始化失败（只是当时不致命）。**判断身份请看"包是否注册 + 进程路径是否在 WindowsApps"这两项。**

## 三、原因（一句话 + 链路）

**26.9xx 起的 Codex 桌面版只支持"以 MSIX 包身份运行"，散装便携版启动必挂。** 而 Codex App Manager 的更新流程恰好把包身份卸掉了：

1. 下载官方 MSIX（876 MB）→ `Add-AppxPackage` 侧载**成功**（包本身没问题）
2. 它做安装后体检的方式是"按 exe 路径起进程"→ 拿不到包身份 → 26.9xx 的 bootstrap 直接退出 → 被判 `healthy=false failure_kind=immediate-exit`
3. 于是它走 portable 回退：把 payload 铺到 `%LOCALAPPDATA%\Programs\Codex`，并 **`Remove-AppxPackage OpenAI.Codex`**（包身份在这一刻被抹掉）
4. 开始菜单 `Codex.lnk` 指向散装 `ChatGPT.exe` → 从此每次启动都死在包身份检查

本机取证（2026-09-26）：

- AppX 事件：17:10:27 `OpenAI.Codex_26.924.2738.0` 部署 **Add 成功** → 17:12:25 发起 **Remove** → 17:12:51 完成并移入 `C:\Program Files\WindowsApps\Deleted\`
- 管理器日志：`MSIX health check result healthy=false … immediate-exit` → `Windows route changed to portable fallback` → `remove MSIX package package=OpenAI.Codex`
- 应用日志：8 次 `bootstrap-import-main` 失败，报错点固定在 `[sparkle] initializeWindowsUpdater → Gw.initialize`
- 同机对照：同一散装路径上的**上一版 26.901.22334 连续跑了两天正常**，更新到 26.924 后才必挂 → 是版本行为变化，不是系统损坏

## 五、修复方案（按优先级）

### 方案一：官方商店装回来（客户机器首选，Windows 管身份）

```powershell
# 商店里搜 ChatGPT 点安装，或：
winget install --id 9PLM9XGG6VKS -s msstore --accept-package-agreements --accept-source-agreements
```

- 商店条目：`https://apps.microsoft.com/detail/9PLM9XGG6VKS`（Publisher = OpenAI，Publisher Url = openai.com/codex）
- 首次走商店可能需要在商店里登录微软账号
- 若报 `0x80070422`，说明 **Microsoft Store 安装服务被禁用**，见方案四

### 方案二：官方 MSIX 离线覆盖安装（无商店 / 已备好包时首选，**本机已验证**）

安装包已归档在本机：

```
D:\software\OpenAI Codex\OpenAI.Codex_26.924.2738.0_x64__2p2nqsd0c76g0.Msix
D:\software\OpenAI Codex\校验.txt        ← SHA256 / 签名者 / 安装与启动命令
```

给客户前先自己核一遍（也请客户核）：

```powershell
Get-FileHash "D:\software\OpenAI Codex\OpenAI.Codex_26.924.2738.0_x64__2p2nqsd0c76g0.Msix" -Algorithm SHA256
# 期望：132431A26FE4DE44D1FA3C6E148506DBB4C8D806DAD40CFD48E3ED554F2755A2
Get-AuthenticodeSignature "D:\software\OpenAI Codex\OpenAI.Codex_26.924.2738.0_x64__2p2nqsd0c76g0.Msix" | Select-Object Status, @{n='Signer';e={$_.SignerCertificate.Subject}}
# 期望：Status=Valid，Signer=CN=50BDFD77-8903-4850-9FFE-6E8522F64D5B
```

安装并启动（**启动必须走应用入口，不要双击 exe**）：

```powershell
Add-AppxPackage -Path "D:\software\OpenAI Codex\OpenAI.Codex_26.924.2738.0_x64__2p2nqsd0c76g0.Msix"
explorer.exe "shell:AppsFolder\OpenAI.Codex_2p2nqsd0c76g0!App"
```

- 提示"已安装更高版本"时用 `Add-AppxPackage -Path <msix> -ForceUpdateFromAnyVersion`
- 包系列名（AppID 前缀）由签名证书派生，正常跨版本不变；万一 OpenAI 换证书，用 `Get-StartApps | Where-Object Name -match ChatGPT` 取当前 AppID

### 方案三：只有 Codex App Manager 时——把它的下载截下来

管理器的 UI **没有"重装/换版本"入口**，只在"检测到更新或未安装"时才下载。所以：

1. 先退出 Codex（任务管理器结束所有 `ChatGPT.exe`）
2. 把 `C:\Users\<用户>\AppData\Local\Programs\Codex` 改名（例：`Codex.old`）→ 管理器主页会变成"**未检测到 Codex**"
3. 打开 Codex App Manager，点 **`安装 Codex`**（安装方式保持"标准安装（MSIX）"）
4. 它会下载约 876 MB（本机实测 10~20 分钟，`.part` 走完后变成正式名）：

   ```
   %LOCALAPPDATA%\Temp\codex-app-manager\staging\downloads\<前缀>-OpenAI.Codex_<版本>_x64__2p2nqsd0c76g0.msix
   ```

   在它这一轮跑完前把该文件拷到别处（拷贝时用 `[IO.File]::Open(..., 'ReadWrite')` 共享读，避免被 curl 占用而失败）
5. 等它结束（`staging` 目录被清空），再按**方案二**安装

> 本机用的自动化脚本思路：轮询 staging → 文件长度等于 `876623361` 才拷贝 → 等 staging 清空 → `Add-AppxPackage` → `shell:AppsFolder` 启动 → 读最新日志判定是否仍报包身份错误。脚本、日志与官方清单留档在 `D:\software\OpenAI Codex\修复脚本与日志\`（`auto-fix.ps1` 全流程 / `make-installable.ps1` 把散装副本挪走 / `uia2.ps1` 用 UI Automation 驱动界面按钮 / `更新后自检.ps1` 更新后一键体检并可 `-Fix` 装回 / `auto-fix.log` 本次执行记录 / `manifest.json`+`checksums.txt` 官方版本与 SHA256）。
>
> 两个使用注意：① 脚本里写死了 `D:\software\OpenAI Codex\` 路径，**拷到客户机时保持同样的目录结构**（或改脚本里的 `$msix`）；② 脚本是 **UTF-8 with BOM** —— PowerShell 5.1 读含中文的 `.ps1` 必须带 BOM，否则会被按 GBK 解析、报"意外的标记"语法错（本机踩过）。
>
> 远程/无桌面、点不到按钮时，可以用 UIA 脚本代替手点（本机即用此法把管理器点进"未检测到 Codex → 安装"状态）：
>
> ```powershell
> powershell -NoProfile -ExecutionPolicy Bypass -File "D:\software\OpenAI Codex\修复脚本与日志\uia2.ps1" -Action dump
> powershell -NoProfile -ExecutionPolicy Bypass -File "D:\software\OpenAI Codex\修复脚本与日志\uia2.ps1" -Action invoke -Name "安装 Codex"
> ```

### 方案四：商店报 `0x80070422` 时——修 Microsoft Store 安装服务

```powershell
Get-Service InstallService        # Disabled 时，winget -s msstore 必然 0x80070422
sc.exe config InstallService start= demand
Start-Service InstallService
```

若 `sc config` 报**拒绝访问**，说明该服务的注册表键被"优化类"工具锁过（本例：键属主 SYSTEM，Administrators 只有 `ReadKey`；而同机 `BITS/Spooler/wuauserv/AppXSvc` 都是 `FullControl`）。恢复默认需要先取得该键所有权再授权 Administrators 写权限——**这属于改动系统安全配置，非必要不做**；不做也不影响方案二/三，装好包之后应用能自己更新。

## 八、以后怎么更新（重要）

优先级从高到低：

1. **让应用自己更新（首选）**：以 MSIX 身份装好后，应用自带 msix 更新通道（日志里 `enableUpdater=true`、`[sparkle] …`，状态目录 `%APPDATA%\Codex\web\Codex\windows-msix-updater\<包系列名>`）。有新版时应用内会提示/自动更新，**不要拦它**。

   > ⚠️ 如实标注：这条通道在**没有包身份**时一直是坏的 —— 本机 09/12、09/19、09/22、09/26 日志里都能看到 `[sparkle] Failed to set up updater … 该进程没有程序标识符`（当时不致命，应用还能跑）；装回包身份后（09/26 修复后）它才第一次正常初始化（`in_app_updates_policy_wait_started`，无报错）。所以"应用自更新"是**证据支持的预期，尚未实测到它真正下载并应用过一次更新**（当时没有新版本发布）。第一次真出现新版本时，请按第六节验收一遍。
2. **官方商店（商店可用时）**：`winget upgrade --id 9PLM9XGG6VKS -s msstore`，或商店里点更新。
3. **离线覆盖安装**：拿到更高版本的官方 MSIX → `Add-AppxPackage -Path <msix>`（同 Publisher 同 Name，高版本会自动覆盖升级）；想跨版本强装用 `-ForceUpdateFromAnyVersion`。
4. **Codex App Manager：只当"下载器"用，不要当"安装器"信**（见下）。

### 还想继续用 Codex App Manager 的话，这样用

它的**价值**：能从国内可直连的镜像把官方 MSIX 拉下来（`codexapp.agentsmirror.com` → 微软商店投递渠道），并做 SHA256 + Authenticode 校验 —— 这是本机唯一实测可用的官方包获取路径（商店被 `InstallService` 锁住，见方案四）。
它的**危险**：安装后"体检"是按 exe 路径起进程（拿不到包身份）→ 误判 `immediate-exit` → 卸掉 MSIX + 回退散装版。

> **为什么"必须自检"**：它的体检结果**环境/状态相关、不可预测** —— 同一个 26.924，本机 09/26 17:10 判失败（随后卸包、应用彻底打不开），把散装副本挪走后的 18:41 再装却判**通过**并保留了 MSIX。所以不能假设"它下次会成功"。

三种安全用法：

- **用法 A（省事）**：照常用它更新 → **更新完立刻跑自检** → 正常就结束；包掉了就用 `-Fix` 装回，两分钟搞定。
- **用法 B（更稳）**：更新前先把 `%LOCALAPPDATA%\Programs\Codex` 改名（如 `Codex.old`），让它走"未检测到 Codex → 安装"的干净路径（09/26 修复时正是这个状态下它的体检**通过**并保留了 MSIX），更新后再跑自检；确认无事再删掉 `Codex.old`。
- **用法 C（最稳）**：只取它的下载、安装自己做 —— 即**方案三**（截获 staging 里的官方 MSIX → `Add-AppxPackage` → 应用入口启动）；这样它的体检与回退都不会生效。

> **红线**：只要经过 Codex App Manager，就必须跑一次自检。它误判的代价是应用彻底打不开，而你不在现场时客户只会认为"你装的东西坏了"。

- 管理器自身可以升级：镜像 `https://codexapp.agentsmirror.com/manager/latest.json` 显示最新 `0.5.10`（`winget` 里只看到 `0.5.6`）。**升级后它的体检逻辑是否修复未知**，所以自检照做。

### 更新后自检（每次更新后都跑一遍）

```powershell
# 只检查（不动系统）
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\software\OpenAI Codex\修复脚本与日志\更新后自检.ps1"

# 发现问题时：自动用留档 MSIX 装回，并以包身份启动
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\software\OpenAI Codex\修复脚本与日志\更新后自检.ps1" -Fix
```

输出示例（正常时）：

```
包注册        : OpenAI.Codex_26.924.2738.0_x64__2p2nqsd0c76g0
进程来源      : WindowsApps（包身份，正常）
日志含身份错误: False
结论: 正常 —— 包已注册，应用以包身份运行
```

手动版就两条命令：

```powershell
Get-AppxPackage -Name OpenAI.Codex | Select-Object -ExpandProperty PackageFullName   # 必须非空
(Get-Process ChatGPT -ErrorAction SilentlyContinue | Select-Object -First 1).Path     # 必须指向 WindowsApps
```

包没了、或路径指向 `Programs\Codex` → 跑自检脚本的 `-Fix`（或方案二），**不要去重装散装版**。

## 九、不要做的事

- ❌ 不要双击 `ChatGPT.exe` 启动（WindowsApps 里的那份也一样）——包身份只能由应用入口（AppUserModelID/AUMID）授予
- ❌ 不要手工 `Add-AppxPackage -Register AppxManifest.xml`：安装目录里那份 manifest 指向 `app\` 与 `assets\`，本地散装目录没有这两个目录，注册不上；且 `packagedServices` 等受限能力拿不到
- ❌ 不要用"重装散装版 / 只结束进程 / 重置商店缓存 / sfc 扫描"这类办法，治不了根
- ❌ 卸载应用前先备份 `%APPDATA%\Codex` 与 `%LOCALAPPDATA%\Codex`
