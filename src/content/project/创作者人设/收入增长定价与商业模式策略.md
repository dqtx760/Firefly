## 一、先说结论

未来 90 天不要继续增加零散服务，而要把现有能力收束成一条升级链：

```text
明确问题的低价排错
→ 标准化 AI 工具配置
→ 个人 AI 工作台 / 单流程自动化
→ 按月维护与优化
```

短期目标分两级：

- 30 天：把月收入从 4000+ 稳定推到 6000 元左右。
- 90 天：验证 8000～10000 元/月，而不是靠偶然的大单或高风险订阅业务冲高。

你的主产品应该是：

> 帮个人创作者、知识工作者和小团队，把 AI 工具装好、配置好，并接入一个真正能使用的工作流。

## 二、目前最需要修正的地方

### 1. 主页定位和服务菜单太散

`dqtx.cc` 的主定位是 Claude Code 与 Obsidian 工作流，但服务区同时放了远程技术支持、会员充值、模板、Codex 手册、网站搭建和顾问咨询。用户会看到“什么都能做”，却不容易判断“我现在应该买什么”。

解决方式：主页第一屏只突出一个主结果，服务区只保留三个主产品，其他服务放到二级页面。

### 2. 低价服务适合引流，不适合承担增长

50～88 元的安装、咨询可以继续保留，但只能处理边界明确的小问题。只要涉及排错、账号环境、多工具联动或工作流搭建，就不能继续按低价小时服务处理。

### 3. 价格口径需要统一

现有资料中出现过 50 元/小时、88 元/小时、Codex 手册 128 元、模板 99～399 元、网站 80～300 元等多个口径。价格不一致会让客户犹豫，也会让你自己在沟通时不断临时报价。

建立一个“唯一报价表”，同步主页、预约页、文章和私聊话术。旧客户按旧约定，新客户按新报价。

### 4. 高风险订阅业务不要作为增长主轴

订阅业务可能有现金流，但售后、平台规则、风控、退款和信誉风险都不是你能完全控制的。它可以作为独立业务观察，但不要把未来收入目标建立在它上面；更不要用“永久稳定”一类无法保证的承诺。

## 三、建议的产品梯度

| 产品 | 首轮测试价 | 交付结果 | 明确边界 |
|---|---:|---|---|
| 基础安装 | 50 元 | 一个常见软件完成安装、启动和基础运行 | 正常 Windows 环境；30 分钟内；不含复杂报错和联动 |
| 诊断与排错 | 199 元 | 定位一个明确问题，给出修复或下一步方案 | 45～60 分钟；一个问题；不含无限追问 |

| 个人 AI 工作台 | 首 3 单 999 元，之后 1499～1999 元 | AI 工具 + 知识库 + 一个 Skill/工作流真正跑通 | 一个具体场景；一次交付调整；不含无限定制 |

| 月度维护与优化 | 首批 999 元/月，之后 1299～1999 元/月 | 每月固定优化、排错和小改动 | 2 次固定沟通或约定时长；不含全天候待命 |

### 报价规则

1. 新客户默认从 199 元诊断开始；7 天内升级项目，可抵扣诊断费。
2. 不再给“帮我看看电脑有什么问题”直接报总价，先把问题变成可验收的任务。
3. 复杂需求必须先写清楚：输入是什么、输出是什么、使用什么工具、验收标准是什么、改几次、多久交付。
4. 50 元只卖“标准安装”，不卖你的排错经验和无限售后。
5. 低价服务出现第二次复杂沟通时，立即转为诊断或项目报价。

## 五、商业模式

### 现金流产品：诊断与标准配置

承接搜索型需求，例如安装失败、报错、API 配置、Codex/Claude Code 无法运行。它的目标不是赚最多，而是快速建立信任并筛选客户。

### 利润产品：个人 AI 工作台

把客户的一个具体工作场景跑通，例如：

- AI 工具 + Obsidian 写作流程
- Codex + 本地文件整理流程
- Claude Code + 内容生产流程
- 一个 Skill + 一个重复业务流程

不要卖“我会很多工具”，要卖“你给我一个场景，我交付一个能跑的结果”。

### 复购产品：维护与优化

只有完成过一次项目、确认客户确实持续使用后，才推荐月度维护。维护服务必须限制次数、时长和响应时间，不能写成“所有问题都可以找我”。

### 资产产品：手册、清单和模板

把重复处理三次以上的问题沉淀成教程、检查清单、SOP 或 Skill。数字产品的作用是筛选和教育客户，不能替代核心交付收入。

暂时不要优先做大课、社群或复杂会员体系。先完成 10 个以上付费核心交付，再根据重复问题决定是否产品化。

## 七、30 天执行计划

### 第 1 周：收口产品

- 确定一个主产品名称：“AI 工具落地与工作流配置”。
- 更新主页，只突出基础安装、诊断排错、AI 工作台三个入口。
- 建立一张统一报价表和客户需求表。
- 写清楚每个产品的交付结果、时长、修改次数和不包含内容。

### 第 2 周：卖出首批测试单

- 联系过去的安装和排错客户，提供 5 个“标准配置”测试名额。
- 发布 3 篇高意图内容，每篇只解决一个具体报错或场景。
- 每个咨询先问：现在卡在哪里、想得到什么结果、是否愿意远程配合。

### 第 3 周：交付并沉淀案例

- 完成 3～5 个付费订单。
- 记录售前沟通时间、实际操作时间、等待时间和售后次数。
- 获得客户允许后，沉淀前后对比、交付清单和常见问题。

### 第 4 周：按数据调价

- 如果 199 元诊断成交稳定且交付不超过 1 小时，保持或提高价格。
- 如果诊断成交但没有项目升级，优先改核心产品的结果描述，不要马上降价。
- 如果项目经常超时，先缩小范围或加价，不要继续用低价换口碑。

## 八、每月必须看的数据

| 指标 | 计算方式 | 用途 |
|---|---|---|
| 平均客单价 | 总收入 ÷ 订单数 | 判断是否脱离低价依赖 |
| 真实时薪 | 总收入 ÷ 售前、交付、售后总小时 | 判断哪些服务值得保留 |
| 诊断成交率 | 付费诊断数 ÷ 有效咨询数 | 判断入口是否清楚 |
| 升级率 | 核心项目数 ÷ 诊断数 | 判断产品是否有价值 |
| 售后率 | 发生额外处理的订单 ÷ 总订单 | 判断边界是否失控 |
| 来源转化 | 各渠道成交数和收入 | 决定内容精力投向 |

## 九、现在需要补充的 6 个数据

为了把测试价改成你的正式价格，请补充：

1. 最近一个月各类订单分别有多少单、各自收入多少？
2. 出单最多的前三类服务是什么？每单平均耗时多少？
3. 客户主要从哪里来：公众号、博客、B 站、小红书、社群、朋友介绍，还是平台接单？
4. 目前每周最多能拿出多少小时做远程交付？
5. 哪一类客户最愿意配合，也最少售后？
6. 你更想优先做到稳定 6000 元、8000 元，还是 1 万元/月？

## 最终判断

你当前已经有真实付费需求，下一阶段的关键不是“再学一个工具”，而是把已有经验包装成可验收、可复用、可升级的服务。保留 50 元入口，但把真正的收入增长放在 399～1999 元的标准化交付和 1299 元以上的持续维护上。
